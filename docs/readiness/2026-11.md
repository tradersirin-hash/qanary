# Solana quantum readiness, November 2026

Read from Solana mainnet on 7 November 2026 at 08:24:12 UTC, slot 466,443,963.
Inputs: [inputs-2026-11.json](inputs-2026-11.json) · Script: [app/scripts/readiness.mjs](../../app/scripts/readiness.mjs)

## Summary

We read who can change 62 programs that hold or move user funds for the 25 largest Solana DeFi protocols (their DefiLlama Solana TVL listings add up to $11.97B, with some overlap) and who can mint or freeze 22 large Solana tokens ($29.38B at Jupiter prices). 61 of the 62 programs can be upgraded. The one that cannot is a legacy swap program deployed with an older loader that has no upgrade path. 18 of the 25 protocols depend on at least one program that can be upgraded with no time lock. 17 of the 22 tokens ($21.64B) have a mint authority, and for 5 of them ($3.80B) a single Ed25519 key can mint on its own. Every member of the 26 Squads and Coral multisigs found behind these programs and tokens is a plain Ed25519 key.

None of this is a flaw under today's threat model. Upgradeable programs, multisigs and issuer-controlled mints are normal practice, and no quantum computer that can break Ed25519 exists. This report maps which keys such a machine would target, so that a migration can be planned before it is urgent. It publishes aggregates only and does not rate any single protocol or token.

## Why it matters

- **Every key that holds an authority is public.** The address of a Solana keypair is its Ed25519 public key, so every authority held by a key, alone or as a multisig member, is public by design.
- **A future quantum computer could sign as that key.** Shor's algorithm, run on a cryptographically relevant quantum computer (CRQC), could derive a private key from its public key and then produce valid signatures for it. No such machine exists today, and nobody knows when or whether one will be built.
- **What a forged signature could do depends on the authority:**
  - an **upgrade authority** can replace a program's code, and with it the rules for every account and token the program holds;
  - a **mint authority** can create new tokens;
  - a **freeze authority** can freeze any holder's token account;
  - a Token-2022 **permanent delegate** can transfer or burn tokens from any holder's account.
- **A multisig of Ed25519 keys is not post-quantum.** It raises the number of keys an attacker must break from one to the threshold (m of n). That is real protection today and would cost an attacker more time, but every member key falls to the same attack.
- **A program-derived address (PDA) has no private key.** A program signs for it, so the question moves to what that program checks before signing, and to who can upgrade that program.
- **A time lock gives users time to react.** It delays an approved change before it can run. It does not stop a forged approval, but it makes the change visible in advance, so users can see it and withdraw before it takes effect.

## Method

**Selection** (full detail, sources and exclusions in [inputs-2026-11.json](inputs-2026-11.json)):

- **Protocols:** the 25 largest by Solana-chain TVL on DefiLlama (`api.llama.fi/protocols`, read 2026-11-07 02:15:35 UTC, Solana entry only). Child listings that share a parent are merged and use DefiLlama's parent figure. Centralized exchanges and chain-level entries are dropped. For each protocol, the mainnet programs that hold user funds or can move them, each taken from an official source (docs, the protocol's GitHub or SDK), or for one legacy program from the DefiLlama adapter that counts it in the protocol's TVL, and checked on-chain as an executable program. Oracles, pricing, fee, governance and non-custodial routing programs are left out. Protocols that run on someone else's program (liquid-staking tokens on stake-pool programs, risk curators) are linked to that program. In alphabetical order: Binance Staked SOL (BNSOL), Bybit Staked SOL (bbSOL), Chainlink CCIP, DFDV Staked SOL (dfdvSOL), Drift, Forward Industries SOL (fwdSOL), Helius Staked SOL (hSOL), Huma, Jito, JPool (JSOL), Jupiter, Kamino, Loopscale, Marinade, Meteora, OnRe, Orca, Phantom SOL (PSOL), Phase.cc, Pump (pump.fun), Raydium, Sanctum, Sentora, Solstice (USX), The Vault (vSOL).
- **Tokens:** the 4,137 tokens on Jupiter's verified list, ranked by on-chain supply times Jupiter price, keeping the top 7 stablecoins, top 5 liquid-staking tokens, top 3 wrapped or bridged assets and top 7 Solana-native tokens. Excluded before ranking: wrapped SOL (no authority), tokenized securities and funds, pool and vault receipt tokens backed by other tokens, and tokens whose quoted value cannot be realized. Each mint was checked against Jupiter's verified flag, CoinGecko's contract field (all but one liquid-staking token, which CoinGecko does not list) and an issuer or operator page (all but one bridged token). In alphabetical order: BNSOL, BP, cbBTC, dSOL, fwdSOL, JitoSOL, JUP, JupSOL, PUMP, PYTH, PYUSD, RAY, RENDER, TRUMP, USD1, USDC, USDe, USDG, USDGO, USDT, WBTC (Wormhole), ZEC (Omni Bridge).

**Sources:** Solana mainnet JSON-RPC (account reads from `solana-rpc.publicnode.com`, transaction history from `api.mainnet-beta.solana.com`): 451 read calls, 10 retries, no fallback needed. Prices from the Jupiter Price API v3 (`lite-api.jup.ag/price/v3`), all 22 tokens priced. TVL from DefiLlama, taken as listed in the inputs and not re-estimated. The census is read-only and never builds or sends a transaction.

**What is read:**

- For each program, its loader and, for the upgradeable loader, its upgrade authority (from the ProgramData account). A program owned by an immutable loader such as BPFLoader2 has no upgrade authority.
- For each mint, its supply, decimals, mint and freeze authority, and for Token-2022 every extension that stores an authority. An SPL Token multisig is decoded to m-of-n with the kind of each signer.
- When an authority is a PDA, the census looks for the program that signs for it. Squads v4, Squads v3, the Coral multisig, SPL Governance and stake-pool withdraw authorities are confirmed by re-deriving the address from the multisig, governance or pool account, and multisigs are decoded (threshold, members, time lock, config authority). Otherwise the controller is inferred from recent and oldest transactions that touched the address or, failing that, taken to be the program that owns the address's account, and marked unconfirmed.

**Classes:**

| Class | Meaning |
|---|---|
| No authority | unset or revoked, or a program that cannot be upgraded (immutable) |
| Single Ed25519 key | one key; its address is its public key |
| SPL Token multisig | (tokens only) m of n listed signers must sign; signers are keys or PDAs |
| Squads v4 multisig | m of n voting members; may have a time lock and a config authority |
| Squads v3 multisig | m of n members; v3 has no time lock |
| SPL Governance | a DAO governance account (Realms or a fork) |
| PDA of another program | an address with no private key that another program signs for; includes the Coral multisig and stake-pool withdraw authorities |
| Unidentified PDA | a PDA whose controller was not found; none among the program, mint and freeze authorities this month |

**Cross-check:** a separate re-read of the 61 upgradeable programs, all 22 mints and the 26 Squads and Coral multisigs, made less than an hour before the census, found the same upgrade, mint and freeze authorities and the same multisig thresholds and time locks. A direct account read after the census (slot 466,448,726) confirmed that the immutable program is an executable account owned by BPFLoader2. Every token value in the results recomputes exactly from supply, decimals and price.

## Limits

- **A snapshot.** Every figure describes the chain at slot 466,443,963, with Jupiter prices read in the same run. Authorities, members, thresholds and time locks can change at any time after the read, and token supplies and prices move continuously.
- **Coverage.** 25 protocols and 22 tokens, not all of Solana. A protocol's program list can miss a program that still holds funds, for example an old deployment its current docs no longer list. The census reads who can replace a program's code. It does not read admin keys kept inside program state (market or vault admins, oracle, pause and fee authorities), which can carry their own powers over funds.
- **TVL attribution.** A protocol's whole TVL is counted under its weakest program, even when that program holds only a small part of it (for example a legacy program). The $11.97B total adds protocols as DefiLlama lists them, so some value is counted twice. Two overlaps are known: one liquid-staking figure includes $1.41B of pools that are also listed as separate protocols, and one risk curator's $373.8M is also counted inside two lending protocols. Value can also sit in more than one protocol, for example a liquid-staking token deposited in a lending market. Read the TVL columns as a sum of listings, not as distinct value.
- **The single-key row.** The one protocol counted under a single Ed25519 key is there only because of a legacy pool program whose upgrade authority is a single key. Its main program is upgradeable by a multisig with a time lock.
- **Inferred PDA controllers.** These authorities are PDAs whose controlling program was inferred, not confirmed by derivation: the upgrade authority of 5 programs (all in one protocol, $265.4M listed TVL), 4 mint authorities ($1.38B), 1 freeze authority ($768.7M) and 1 Token-2022 transfer-hook authority. For 1 of the mint authorities and the freeze authority, no signing use was seen in the examined transactions, so the controller is the program that owns the account. One Squads v4 config authority (on a multisig that can upgrade 2 programs) is a PDA whose controller was not identified. The program, protocol and token counts in the summary do not depend on these, but 3 of the 21 Squads v4 multisigs in Table 5 were found only through them, as upgrade authorities of inferred controller programs.
- **What classes do not say.** A class tells who can sign today. It does not show who the members of a multisig are, whether one person holds several member keys, how a DAO votes, or how quickly anyone would notice a change. SPL Governance voting and hold-up times were not decoded.
- **Prices and value.** Token value is full mint supply times the Jupiter price at the read. For some stablecoins that supply includes balances the issuer still holds, so it is above the circulating figure. When the inputs were built, Jupiter prices agreed with CoinGecko within 0.7%, with two exceptions among the liquid-staking tokens: for one, Jupiter matched the pool's on-chain exchange rate and CoinGecko did not; the other is not listed on CoinGecko.
- **Timing of the threat.** The census shows which kinds of keys sign. It does not estimate when or whether a cryptographically relevant quantum computer will exist, or what an attack would cost.

## Reproduce

The script and inputs are in this repository. With Node 22, from a fresh clone:

```bash
cd app
npm ci
node scripts/readiness.mjs --in ../docs/readiness/inputs-2026-11.json --out readiness-results-2026-11.json
```

The script prints the aggregates and writes every protocol, program and mint, with the evidence behind each authority, to the output file. This report used the defaults: `--max-sigs 40 --max-txs 12 --oldest-pages 5 --oldest-txs 4 --delay-ms 150`. `node scripts/readiness.mjs --self-test` checks the classifier against known mainnet accounts. Both commands only read from public endpoints, and a re-run will differ where the chain has changed since slot 466,443,963.
